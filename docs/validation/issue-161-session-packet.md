## Choose: identify the build and purpose

WIN-PCInfo helps an operator and consultant understand one Windows device and
plan follow-up. An observation is a source fact; coverage says what was examined;
a finding interprets admitted evidence; a recommendation suggests later work.
An Indeterminate finding identifies missing context. The application does not
certify compliance, assess a tenant, or perform remediation.

## Prepare and run: beginner launch guide

1. Receive root's exact approved private archive and its verification record.
   Extract it into the verified private local folder. Keep its files together.
   Do not use the unsigned development precursor for ordinary collection.
2. Double-click **Start-WIN-PCInfo.cmd**. Read visible runtime, policy or trust
   guidance if launch refuses. Do not bypass policy, unblock/sign different bytes,
   install a runtime mid-run or elevate the GUI by default. Root resolves admission.
3. In the Status desk, read the four preparation facts, complete scope, output
   destination, prerequisites, expected time/storage, cleanup, network behavior,
   privilege and package-protector information. Select **Comprehensive Local
   Assessment**. Final acceptance requires all selected families.
4. Choose **Local Only** first. Change network/output choices only before approval.
   Select zero or one previously verified recipient; confirm its fingerprint through
   the established trusted contact. Separate recipient setup is deliberate, never
   a prompt inside collection. A changed choice requires a fresh complete plan.
5. For the first check, decline preparation. Expect NotStarted, no assessment
   collection or network request, and no new package. Then start a fresh preparation,
   review it again and approve once. Complete only the anticipated Windows UAC or
   key-provider interaction directly. The run should need no further authority.
6. Follow phase/activity text and elapsed time. Move, resize and use the keyboard
   while observing progress. A heartbeat means the coordinator is responsive; it
   does not claim new source observations or a percentage of completed work.
7. At the terminal result, read coverage, package availability and cleanup first.
   Use **Open report** when a verified package exists. Use **Close viewing** to end
   the protected viewing session and verify plaintext cleanup. Missing results or
   failed integrity must not enable report actions.
8. After verified cleanup, use **New preparation / retry** for the separately
   approved Microsoft Connectivity Enabled run and other planned scenarios.
   Review the disclosed endpoint/protocol plan before approving. Never change
   network mode during an active assessment.

Normal completion is `Completed/0`; honest gaps are `CompletedWithGaps/10`.
Other terminals are `NotStarted/20`, `Cancelled/30`, `TimedOut/40`,
`IntegrityFailed/50`, and `CleanupIncomplete/60`. GUI, record, Completion Summary,
exit status, package and cleanup must agree. A cancelled run may have a protected
usable partial result or no usable package; neither implies completion.
