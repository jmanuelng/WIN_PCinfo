# Effective management policy, platform protection, and application control

This preview slice answers three related but different questions after the operator approves the immutable Preparation Plan:

1. **Applied Policy Evidence** reads the locally cached Resultant Set of Policy (RSoP) logging namespaces for the Assessment User Context and the computer. The initiating process proposes a private SID through the authenticated, ACL-protected one-run channel. Inside the already authorized privileged operation, the worker verifies that SID and the coordinator session against local WTS/LSA data before and after user RSoP, and uses the cached user namespace with underscore-separated SID components. Missing or changed verification leaves a scoped gap. An alternate operator or administrator therefore cannot substitute their own user policy. It records bounded policy-object identity, enabled link state, link identity, and precedence only for the release-cataloged `RSOP_RegistryPolicySetting` extension. The base-class query reads only finite identity/reference fields so another derived extension becomes explicit `Unsupported` coverage; an extension-relative `id` is never treated as globally unique. It does not refresh Group Policy, contact a domain controller, enumerate unapplied policy, or parse a localized report.
2. **Configured Policy Signals** reads three exact local registry values for machine inactivity timeout, secure-attention-sequence behavior, and LAN Manager compatibility level. It also reads the release-owned Defender preference fields for attack-surface reduction GUID/action pairs and Network Protection, plus SmartScreen shell and app-install policy signals from their exact registry locations. This slice also adds the finite local Windows Update and Windows Update for Business registry mappings for feature-update deferral, quality-update deferral, and `DisableDualScan`, plus the bounded legacy-authentication registry names and masks for LAN Manager compatibility and NTLM minimum session security. A value is a configured signal only. It does not prove who configured it, why it exists, whether another mechanism currently enforces the related control, or that Windows actually used the related legacy protocol.
3. **Policy CSP result signals** reuse the predefined SYSTEM sub-plan to read one fixed `MDMWinsOverGP` flag and the same three security-option fields from the release-owned Windows 10 and Windows 11 `MDM_Policy_Result01_*` catalogs. `MDMWinsOverGP` is reported only for that documented Policy CSP scope. WIN-PCInfo does not turn it into a blanket claim that all MDM, Intune, CSP, or tenant policy wins over Group Policy.
4. **Current Control State** reads the local SAM account and lockout policy, three Audit Policy subcategories, and three direct LSA user-right assignments. It also records Windows Security Center antivirus and firewall provider identity/health, Microsoft Defender Antivirus runtime mode and protection flags, tamper protection, the ActiveStore Domain, Private, and Public firewall profile state, BitLocker operating-system-volume conversion/protection/encryption/lock state, bounded BitLocker protector type/count evidence, and device-reported VBS, Credential Guard, memory-integrity, and user-mode code-integrity runtime state. This slice also records local RDP connection allowance, service mode/state, authentication settings, and listener state; local WinRM service mode/state, `AllowUnencrypted`, authentication settings, and listener state; plus SMB client posture, SMB server posture, and SMB1 optional-feature state. These are local configuration and service observations only. WIN-PCInfo does not try an RDP or WinRM connection, enumerate SMB shares or sessions, or turn one endpoint's posture into an organization-wide exposure claim. Local SAM policy applies to local accounts, not domain accounts. A user-right SID is a direct assignment only; WIN-PCInfo never expands groups to guess effective access.
5. **Structured application-control signals** record WDAC inventory only through the structured `CiTool -lp -json` surface and only on supported builds. Unsupported Windows 10 inventory remains an explicit coverage gap instead of parsed text. WIN-PCInfo also keeps AppLocker Group Policy and AppLocker CSP channels separate. It records only bounded rule-collection and enforcement-mode facts and marks incomplete or conflicting channel combinations as Indeterminate or NeedsAttention instead of guessing a winner.

Registry values do not expose a trustworthy last-applied timestamp through the approved read-only interface. The live collector therefore reports source attribution and freshness as unproven; it never labels a value fresh or stale. The synthetic `StaleRegistry` case verifies that an upstream typed stale state would remain an explicit gap, but it is not a claim that this preview detects live registry staleness.

## Sources and bounds

The frozen operation is `observe-effective-policy`. It runs once in the already-approved Administrator worker, offline, for at most five seconds, with a 16 KiB result ceiling. It may not prompt again, install or download a tool, invoke a caller command, write policy, refresh policy, or open a network connection.

The locale-neutral structured source catalog is:

- cached `RSOP_GPO` and `RSOP_GPLink` instances plus the finite `RSOP_RegistryPolicySetting` setting class in the Assessment User SID-specific and computer namespaces; the abstract `RSOP_PolicySetting` query is used only to detect and reject unsupported derived extensions;
- `NetUserModalsGet(NULL, 0)` and `NetUserModalsGet(NULL, 3)` for local SAM policy;
- `AuditQuerySystemPolicy` for the exact Logon, Process Creation, and User Account Management subcategory GUIDs;
- `LsaEnumerateAccountsWithUserRight` for `SeRemoteInteractiveLogonRight`, `SeDenyRemoteInteractiveLogonRight`, and `SeServiceLogonRight`; and
- Windows Security Center provider registration and health through the supported Windows Security Center interface for Antivirus and Firewall;
- `Get-MpComputerStatus` for Defender runtime mode, protection flags, and tamper state;
- `Get-MpPreference` for the release-owned Defender preference catalog of ASR rule GUID/action pairs and Network Protection;
- `Get-NetFirewallProfile -PolicyStore ActiveStore` for Domain, Private, and Public firewall profile state;
- `Get-BitLockerVolume` for the operating-system-volume status and bounded protector type/count projection only;
- `Get-CimInstance Win32_DeviceGuard` for device-reported VBS, Credential Guard, and code-integrity runtime state only;
- `CiTool -lp -json` for structured WDAC policy inventory on supported builds only;
- `Get-AppLockerPolicy -Effective` for the Group Policy AppLocker channel only;
- `Get-CimInstance MDM_AppLocker_*` for the separate AppLocker CSP channel only;
- the predefined SYSTEM sub-plan over `Root\cimv2\mdm\dmmap`, restricted to `MDM_Policy_Result01_ControlPolicyConflict02`, `MDM_Policy_Result01_LocalPoliciesSecurityOptions02`, and `MDM_Policy_Result01_Update02` plus the seven release-owned properties;
- read-only `Microsoft.Win32.Registry.LocalMachine.OpenSubKey` calls for the three release-cataloged local security-option signals, the release-cataloged SmartScreen policy signals, the finite Windows Update/WUfB registry mappings, and the bounded legacy-authentication registry names and masks;
- `Get-CimInstance Win32_Service`, `Get-CimInstance Win32_TSGeneralSetting`, and the exact Terminal Services registry location for local RDP configuration, service, authentication, and listener state only;
- `Get-ChildItem WSMan:\localhost\Service`, `Get-ChildItem WSMan:\localhost\Service\Auth`, `Get-ChildItem WSMan:\localhost\Listener`, and `Get-CimInstance Win32_Service` for local WinRM service, authentication, and listener state only; and
- `Get-SmbClientConfiguration`, `Get-SmbServerConfiguration`, and `Get-WindowsOptionalFeature -Online -FeatureName SMB1Protocol` for structured SMB client, server, and SMB1 feature state only.

## Missing and conflicting evidence

A successfully queried empty RSoP namespace or an absent enabled link is represented as observed absence. Multiple enabled links, missing namespaces, individual missing RSoP classes, an unsupported setting extension, a failed NetAPI level, denied sources, an upstream typed stale registry signal, unavailable registry signals, malformed values, timeouts, cancellation, unsupported WDAC inventory, incomplete AppLocker channels, absent WinRM or RDP listeners, unsupported or missing SMB1 feature-state observations, and incomplete Windows Update or legacy-authentication fields remain field-specific Evidence Coverage gaps with diagnostics. The frozen eight-policy and eight-setting ceilings are checked before projection; overflow retains only the bounded subset and reports `Partial` with `POLICY.RSOP_EVIDENCE_BOUND_EXCEEDED`. Negative or zero precedence and ambiguous links are never clamped or selected. These conditions never become a false empty policy, an affirmative setting, a claim that remote management is unreachable, or a claim that a legacy protocol was not used.

Seven bounded rules produce separate findings:

- whether applied-policy evidence is complete;
- whether the finite local-security catalog is complete;
- whether the same setting has competing policy objects in the observed precedence data;
- whether the Defender, SmartScreen, Windows Security Center, firewall, BitLocker, VBS, WDAC, and AppLocker state catalog is complete;
- whether a passive-mode or tamper-protected Defender state, local BitLocker protection state, or virtualized VBS state is present as an explicit constraint rather than a generic failure;
- whether the Policy CSP result catalog is completely observable on the current build; and
- whether the local configured signal and the Policy CSP result disagree for one of the three release-cataloged settings, or the AppLocker GP and CSP channels disagree for the same rule collection.

An observed conflict is `NeedsAttention`, not a compliance failure or remediation instruction. Insufficient evidence is `Indeterminate`. If Policy CSP coverage is incomplete, or if a local signal and a Policy CSP result disagree, WIN-PCInfo emits tenant-side discovery tasks instead of guessing assignment intent, winning source, remediation, compliance, or organization-wide state. WIN-PCInfo does not assign an overall score, infer organizational intent, or change a policy.

## Privacy and troubleshooting

Policy object IDs, link paths, setting IDs, configured values, Security Center provider names, ASR GUIDs, local account-policy values, Windows Update and Policy CSP values, remote-management listener details, SMB posture values, BitLocker protector identifiers or recovery material, AppLocker policy bodies, WDAC policy bodies, and assigned principal SIDs are Restricted Diagnostic Evidence. They appear only in the canonical record and beginner report inside the Protected Evidence Package when they are admitted at all. Progress and public validation output contain only release-owned states, findings, counts, and safety assertions.

If the report shows an RSoP gap, confirm that the device has a locally cached logging-mode RSoP namespace; do not install a tool merely to satisfy this preview. If a local source is denied, rerun only through the approved Preparation flow and its single UAC boundary. If a configured signal is unavailable, malformed, or another trusted source indicates it may be stale, treat the related finding as Indeterminate and investigate through the organization’s authorized policy-management process. If Windows Update or WUfB values are incomplete, confirm the documented registry or Policy CSP sources instead of starting an update scan. If RDP or WinRM listeners are absent or incomplete, treat that as local configuration coverage only; it does not prove whether another host can or cannot connect. If SMB posture is incomplete, do not enumerate shares or sessions to fill the gap. If legacy-authentication values are missing or incomplete, do not convert that gap into a claim that NTLM, SMB1, or another legacy protocol was unused. If WDAC inventory is unsupported, confirm the Windows build instead of parsing text output. If AppLocker GP and CSP disagree or one channel is incomplete, confirm deployment channel, assignment scope, and intended precedence through the organization’s authorized policy-management process rather than guessing from one device. If BitLocker shows local protection, treat that as local state only; it does not prove recovery escrow, and virtual evidence does not prove physical TPM attestation.
